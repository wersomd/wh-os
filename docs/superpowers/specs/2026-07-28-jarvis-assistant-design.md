# Джарвис — AI-ассистент для Wediff (спек 1 из 3)

**Дата:** 2026-07-28
**Статус:** одобрено, к реализации
**Часть большого плана:** Джарвис → редизайн дашборда → DevOps-панель (Supabase/Vercel). Это первый и центральный кусок; остальные два — отдельные спеки позже.

## Цель

Личный AI-ассистент («Джарвис») поверх Wediff: командная строка (⌘K), которая
понимает вопросы и команды на естественном языке по 4 рабочим модулям —
**задачи, финансы, долги, подписки** — отвечает и, с подтверждением, меняет данные.

## Ключевые решения (зафиксированы)

- **Форма UI:** командная строка ⌘K с выпадающим стримящимся ответом (не отдельный чат, не виджет).
- **Уровень ума:** настоящий AI на Claude (не правила, не локальная модель).
- **Модель:** `claude-opus-4-8` по умолчанию; вынесена в конфиг для лёгкого переключения на `claude-haiku-4-5`.
- **Запись:** только с подтверждением пользователя перед каждым write-действием. Чтение — сразу.
- **Охват v1:** 4 модуля. Остальные 9 — позже.
- **Ключ:** `ANTHROPIC_API_KEY` в `.env`, вызовы только на сервере (server action) — ключ не попадает в браузер.

## Архитектура

```
⌘K  →  JarvisBar (client)  →  askJarvis (server action)  →  Claude Opus 4.8
                                      │                          │
                                      │   ← tool_use (read) ─────┘
                                      │   выполняется сразу (features/*/queries.ts)
                                      │
                                      │   ← tool_use (write)
                                      └── ПАУЗА → карточка подтверждения → [Ок]
                                            └── выполняет (features/*/actions.ts) → продолжает loop
```

- Новый модуль `src/features/jarvis/` по конвенции проекта.
- Чтение — через существующие `queries.ts`; запись — через существующие `actions.ts`.
  Джарвис **не дублирует** бизнес-логику и Zod-валидацию, а вызывает готовое.
- Официальный `@anthropic-ai/sdk` (проект на TS). Стриминг ответа.

### Компоненты и их границы

| Юнит | Ответственность | Зависит от |
|---|---|---|
| `components/jarvis-bar.tsx` (client) | ⌘K, поле ввода, рендер стрима, карточки подтверждения, память в пределах сессии | `actions.ts` (server action) |

## Поток подтверждения (ядро безопасности)

Ручной agentic-loop без сохранения состояния на сервере (server actions stateless):

1. `askJarvis(messages)` крутит loop: Claude → tool_use.
2. **Read-инструмент** → выполняется сразу, `tool_result` кладётся обратно, loop продолжается.
3. **Write-инструмент** → loop **останавливается** и возвращает клиенту:
   - текст ассистента, накопленный на данный момент;
   - `pendingAction`: имя инструмента, **уже провалидированный** Zod-ввод, человекочитаемое резюме («Создать задачу "X" на 29 июля?»);
   - полную историю сообщений (включая `assistant` с блоком `tool_use`).
4. Клиент рендерит карточку `[Ок] [Отмена]`.
5. **Ок** → `confirmAction(history, approved=true)`: сервер исполняет write через `features/*/actions.ts`, кладёт `tool_result`, продолжает loop.
   **Отмена** → `tool_result` = «пользователь отклонил», loop продолжается (Джарвис объясняет/предлагает иначе).

Несколько write-действий подряд обрабатываются по одному (по каждому — своя карточка).

## Инструменты v1

| Модуль | Read | Write (с подтверждением) |
|---|---|---|
| Задачи | найти/список по фильтрам (статус, срок, проект) | создать; отметить выполненной; перенести срок |
| Финансы | сумма трат/доходов за период; баланс по счетам; топ-категорий | добавить транзакцию |
| Долги | кто/сколько должен; просрочки; чистый баланс | отметить платёж/погашение |
| Подписки | ближайшие списания; сумма в месяц | добавить; отменить |

Каждый инструмент = Zod-схема ввода + тонкий исполнитель поверх существующего кода модуля.
Деньги — `Decimal(14,2)`, валюта по умолчанию KZT (как в проекте).

## UI-детали

- `JarvisBar` монтируется в `src/app/(app)/layout.tsx` (клиентский островок внутри серверного layout).
- Хоткей ⌘K / Ctrl+K; Esc — закрыть.
- Ответ стримится. Под ним — предлагаемые кнопки-переходы (`Открыть финансы` и т.п.).
- Память **в пределах открытой сессии** панели; закрытие очищает контекст.

## Обработка ошибок

- Нет `ANTHROPIC_API_KEY` → понятное сообщение в панели («Джарвис не настроен: добавьте ключ в .env»).
- Ошибка API Anthropic (rate limit / сеть) → типизированный перехват, дружелюбное сообщение, кнопка «повторить».
- Ошибка Zod-валидации ввода инструмента → возвращается модели как `tool_result` с `is_error`, чтобы она переспросила/исправилась.
- `stop_reason: "refusal"` → показать корректный отказ, не падать на чтении `content`.

## Тестирование

- Юнит: маппинг инструментов (Zod-ввод → корректный вызов исполнителя), формирование `pendingAction`, ветка отмены.
- Интеграция (моками Anthropic): read-запрос без подтверждения; write-запрос с подтверждением и с отменой.
- Ручная проверка в реальном приложении по каждому из 4 модулей.
